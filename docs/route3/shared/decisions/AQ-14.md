# AQ-14 — LangGraph, LangChain and test-runner versions

**Story:** R3-101 (Sprint 1, Epic E0)
**Status:** Proposed — needs owner approval
**Baseline:** `7c38c5047efce336dc2451e23a3f0b0ebdc1512f`
**Constraint (owner):** no upgrade of the packages the server already declares: `langchain ^0.3.33`, `@langchain/openai ^0.6.11`, `zod ^4.2.1`.
**Sources:** `server/package.json`, installed `server/node_modules`, and the npm registry, read on 2026-10-15. Nothing was installed.

## 1. Decision proposed

| Package | Proposed | Why |
|---|---|---|
| `@langchain/langgraph` | **`0.4.10`** (exact) | Newest version that accepts `@langchain/core` 0.3. Every 1.x release needs `@langchain/core ^1`. |
| `@langchain/core` | **`0.3.80`** (exact, declared directly) | Already installed through `langchain` and `@langchain/openai`. Declaring it makes the version Route3 imports explicit. No upgrade. |
| `vitest` | **`5.0.5`** (exact, dev only) | Current stable. Fallback: `4.1.12` if 5.x fails the R3-102 checks. |
| Zod in Route3 code | **`zod` (v4)**, with **`zod/v3`** as the fallback | See §3. The fallback is chosen only if the R3-102 compatibility tests fail. |

`langchain`, `@langchain/openai` and `zod` stay as they are.

## 3. Findings

### 3.1 LangGraph

| Version | `@langchain/core` peer | Zod | Fits the constraint |
|---|---|---|---|
| **0.4.10** (2026-08-19) | `>=0.3.58 <0.4.0` → 0.3.80 ✅ | own `zod ^3.25.32`; peer `zod-to-json-schema ^3.x` (3.25.1 installed ✅) | **Yes** |
| 1.0.0 → 1.5.0 (latest) | `^1.0.1` → `^1.1.48` | peer `zod ^3.25.32 \|\| ^4` | **No**: needs `@langchain/core` 1.x, which `langchain` 0.3 and `@langchain/openai` 0.6 do not accept |

0.4.10 pulls `@langchain/langgraph-checkpoint ^0.1.3` (accepts core `>=0.2.31 <0.4.0`) and `@langchain/langgraph-sdk ~0.1.10`. It supports Node ≥ 18.

### 3.2 Zod 4 with LangChain 0.3

- `@langchain/core` 0.3.80 has "interop" Zod types. `tool()` has overloads for Zod v3 **and** v4 object schemas (`ZodObjectV3`, `ZodObjectV4`), and `withStructuredOutput` accepts `InteropZodType`.
- It turns v4 schemas into JSON Schema with `toJSONSchema` from `zod/v4/core` — but from **its own nested zod 3.25.76**, not from the server's zod 4.3.6.
- **Not proven:** that schemas built with zod 4.3.6 convert and validate correctly through the 3.25.76 copy of `zod/v4/core`. The types say yes; no test has run it.
- **Fallback:** zod 4.3.6 ships a `zod/v3` subpath. Route3 code could import `zod/v3`, which takes LangChain's long-standing v3 path (`zod-to-json-schema`).

### 3.3 Route2 does not use LangChain

No file under `server/src` or `server/tests` imports `langchain` or `@langchain/*`. Route2 calls LLMs through its own `LLMProvider`. Adding LangGraph cannot change what Route2 loads or does.

### 3.4 Vitest

- `vitest` 5.0.5 needs Node `^22.12.0 || ^24.0.0 || >=26.0.0` — met locally and in Docker. It is a dev dependency only and never ships in the image.
- It runs TypeScript and ESM (`"type": "module"`) itself; `tsx` is not needed for it. It peers on `vite ^6.4 || ^7 || ^8`, which R3-102 pins if npm does not add it.
- Route2 keeps `node --test`; the two runners do not share files or configuration.

## 4. Gates for R3-102 (must pass before the versions are final)

R3-102 adds these Vitest tests, with fake models only:

1. A `tool()` with a zod 4 object schema produces the expected JSON Schema and rejects invalid input.
2. `withStructuredOutput` on a fake chat model parses a zod 4 schema result, and rejects an invalid one.
3. A minimal LangGraph `StateGraph` runs one fake LLM → tool → observation → LLM round.
4. `npm test` (Route2) passes unchanged, and `npm ls` shows no upgraded `langchain`, `@langchain/openai` or `zod`.

If 1 or 2 fail, Route3 switches to the `zod/v3` import (§3.2) and the tests are repeated. If 3 fails, or Vitest 5 fails on Windows, R3-102 stops and reports.

## 5. Risks and alternatives

- **Two zod copies.** Route3 code and LangChain see different zod builds. Gates 1–2 are there to catch it.
- **LangGraph 0.4 is the old line.** Newer LangGraph features and fixes land in 1.x only.
- **Alternative (not proposed):** move the whole stack to LangChain 1.x (`langchain` 1, `@langchain/core` 1, `@langchain/openai` 1, LangGraph 1.5), which supports zod 4 natively. That breaks the owner's no-upgrade constraint. Since Route2 does not import LangChain (§3.3), the upgrade would be low-risk if the owner later wants it.
